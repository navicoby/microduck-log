MicroDuck 강화학습 훈련일지

소형 이족보행 로봇 MicroDuck의 움직임을 강화학습으로 구현하는 실험 기록입니다. 노트북 GPU 한 대에서 보행, 앉았다 일어서기, 점프, 낙상 후 기립을 시뮬레이션으로 학습하고 평가합니다.

비슷한 실험을 설계하는 사람이 참고할 수 있도록 실험 조건, 관측 결과, 결과에 대한 해석을 구분해 정리했습니다. 성능 변화뿐 아니라 평가 오류와 가설을 수정한 과정도 함께 기록합니다.

기록 범위는 2026년 9월 1일부터 현재까지의 시뮬레이션 실험이며, 매일 갱신합니다(마지막 갱신 2026-10-08). 아래 수치와 영상은 실제 로봇에서 검증한 결과를 뜻하지 않습니다.

실험 당시 의존성 잠금 파일은 Linux 환경에 CUDA 패키지를 지정하고 있었습니다. Windows에 직접 설치했을 때는 CPU용 PyTorch가 선택되어 GPU 초기화에 실패했고, 이후 WSL2에서 환경을 구성했습니다. 파일 입출력 성능은 작업 파일의 위치에도 영향을 받으므로, WSL의 Linux 파일시스템과 /mnt/c 중 어느 경로를 사용하는지 실행 조건에 함께 기록하는 것이 좋습니다.

주요 용어

아래 용어는 학습 설정과 날짜별 기록에서 같은 의미로 사용합니다.

PPO
Proximal Policy Optimization. 환경과의 상호작용으로 수집한 데이터로 정책을 갱신하는 강화학습 알고리즘입니다. 이 실험의 클리핑 설정은 새 정책과 이전 정책의 행동 확률비가 목적함수에 미치는 영향을 제한해 급격한 갱신을 억제합니다. 설정값은 0.2입니다. 알고리즘 원문
정책
관측값을 입력받아 로봇의 행동 명령을 출력하는 신경망입니다. 이 실험에서는 관절 제어에 사용할 14차원 행동을 생성합니다.
액터 · 크리틱
액터는 행동을 선택하는 정책이고, 크리틱은 앞으로 얻을 보상의 기대값을 추정해 학습을 돕습니다. 비대칭 구성에서는 크리틱에만 시뮬레이터 내부 정보를 추가로 제공하며, 실행용 정책에는 액터를 사용합니다.
학습 회차
병렬 환경에서 데이터를 수집한 뒤 정책을 갱신하는 한 주기입니다. 한 회차에는 여러 시뮬레이션 스텝과 여러 번의 최적화가 포함됩니다. 에피소드 수나 물리 시뮬레이션 스텝 수와는 다릅니다.
병렬 환경
독립적으로 실행되는 시뮬레이션 인스턴스입니다. 4,096개 환경은 로봇 4,096개체의 경험을 병렬로 수집한다는 뜻입니다.
웜스타트
이미 학습된 정책을 초기값으로 사용해 새 과제를 학습하는 방법입니다. 이 기록에서는 보행 정책이나 착지 정책에서 점프 학습을 시작했습니다.
체크포인트
학습 중간에 저장한 모델 상태입니다. 중단된 학습을 재개하거나 회차별 성능을 비교할 때 사용합니다. 이 실험의 저장 간격은 250회차입니다.
커리큘럼
학습 진행에 따라 과제 난도나 보상·벌점의 적용 범위를 조절하는 방법입니다. 점프 실험에서는 낙상 벌점을 단계적으로 도입하는 구성을 사용했습니다.
엔트로피
행동 분포의 퍼짐 정도를 나타내는 지표입니다. 동일한 행동 정의와 척도에서 값이 감소하면 탐색 범위가 좁아졌을 가능성을 살펴봅니다. 연속 분포의 엔트로피는 음수가 될 수 있으므로 부호만으로 학습 실패를 판정하지 않습니다.
도메인 무작위화
마찰, 질량, 센서 오차 등의 조건을 바꾸며 학습하는 방법입니다. 특정 시뮬레이션 조건에 대한 과적합을 줄이려는 목적이며, 실제 로봇에서의 성능은 별도로 평가해야 합니다.
ONNX
학습한 신경망을 다른 실행 환경에서 사용할 수 있도록 저장하는 모델 형식입니다. 이 구성에서는 관측 정규화 연산을 포함해 정책을 내보냅니다.

액터의 입력은 고유수용 관측 48차원과 명령 13차원으로 구성됩니다. 고유수용 관측에는 각속도, 중력 투영 벡터, 관절 위치·속도, 직전 행동이 포함됩니다. 명령은 속도 3차원, 머리 자세 4차원, 몸통 자세 6차원입니다. 지면 높이 스캔은 입력하지 않으므로, 이 보행 정책은 지형 형상을 직접 관측하지 않습니다.

도메인 무작위화는 세 시점에 적용했습니다. 실행 시작 시에는 마찰·엔코더 편향·질량중심·관성을, 환경 초기화 시에는 질량중심·관절 마찰·관절 추가 관성(armature)·자세를 변화시켰습니다. 학습 중에는 주기적으로 외부 밀기 힘을 가했습니다. 기본 구성의 일곱 커리큘럼 항은 모두 2,000회차에서 최종 단계에 도달하며, 이후에는 해당 설정을 유지합니다.

보행 과제의 보상은 15개 항으로 구성되며, 별도의 낙상·종료 벌점은 없습니다. 초기 점프 과제에는 낙상 벌점 −500을 적용했고, 9월 23~24일의 v5·v6·v7은 이를 단계적으로 도입하도록 설정했습니다. 그러나 9월 30일에 확인한 바로는 웜스타트 시 학습 스텝 카운터가 복원되어 이 설정이 적용되지 않았고, 세 실행 모두 첫 회차부터 −500이 걸려 있었습니다(9월 30일 기록). 단계적 도입이 실제로 작동하는 첫 실행은 9월 30일에 시작한 v8입니다.

피지컬 AI 관점에서의 실험 범위

이 실험은 로봇이 자신의 상태와 명령을 관측하고, 행동의 결과를 보상으로 받아 움직임을 학습하는 과정을 다룹니다. 병렬 시뮬레이션에서 경험을 수집하고, 보상 설계와 초기 정책을 바꾸며 보행·점프·기립 성능을 비교합니다.

핵심은 동작의 외형뿐 아니라 정책이 어떤 조건에서 동작을 습득하고, 유지하거나 잃는지를 확인하는 데 있습니다. 보상값, 성공률, 낙상률과 함께 평가 기준이 의도한 움직임을 제대로 구분하는지도 검토합니다.

  • 학습 방식 — 사람이 설계한 보상으로 PPO 정책을 학습했습니다. 사람의 동작 데이터를 이용한 모방학습은 적용하지 않았습니다.
  • 시각 입력 — 단안 RGB 카메라를 사용하는 학생 정책의 관측 인터페이스를 구성하고 센서 입력을 점검했습니다. 교사 정책의 행동을 학생에게 전달하는 증류 학습의 성능 결과는 아직 없습니다.
  • 적용 범위 — 특정 로봇의 동작별 정책을 대상으로 합니다. 여러 로봇과 과제를 포괄하는 범용 모델의 성능을 평가한 기록은 아닙니다.

계단 통과 한계 평가와 점프 높이 추정의 정정

수행 내용계단 높이를 바꾸며 기존 정책의 통과 성능을 평가했습니다. 점프의 물리적 가능성을 계산하고, 앉았다 일어서기 과제의 학습을 시작했습니다.

측정 오류와 평가 시 확인할 사항

실험 과정에서 발견한 측정·집계 오류를 정리했습니다. 수치를 비교하기 전에 평가 길이, 종료 조건, 좌표계, 성공 판정이 같은 의미로 사용되는지 확인하는 데 참고할 수 있습니다.

  1. 후보 체크포인트 선택 기준을 학습 전에 정합니다 평가값이 가장 높은 체크포인트를 사후에 고르면 선택 자체가 결과를 끌어올립니다. 이 저장소는 웜스타트 시 회차 번호를 이어받아 첫 체크포인트가 학습 전 정책이므로, 최고값 선택은 초기 정책의 성능을 학습 결과로 보고하는 결과로 이어질 수 있습니다. 9월 23~24일 기록에서 이 오류가 있었고 초기값과 종료값을 함께 제시하도록 정정했습니다.
  2. 낙상률의 분모와 에피소드 종료 사유를 확인합니다 초기 평가에서는 낙상률이 100%로 집계되는 문제가 있었습니다. 평가 구간 안에 종료된 에피소드만 집계하면, 아직 진행 중인 정상 에피소드가 분모에서 빠질 수 있습니다. 평가 길이와 최대 에피소드 길이를 함께 기록하고, 낙상·시간 초과·미종료를 구분해야 합니다. 초기 기록의 스텝 수 설명에는 불일치가 있어 특정 길이 배수를 일반 규칙으로 제시하지 않습니다.
  3. 평가 길이가 다른 낙상률을 직접 비교하지 않습니다 2,000스텝과 3,500스텝으로 평가한 낙상률을 같은 조건의 결과로 비교한 오류가 있었습니다. 비교 실험에서는 평가 길이와 초기 조건, 명령 분포를 맞춰야 합니다.
  4. GPU 메모리 지표의 측정 범위를 확인합니다 사용한 Windows·WSL2 환경에서는 병렬 환경 2,048개의 메모리 사용량이 4,096개보다 크게 보고된 사례가 있었습니다. 표시값만으로 가용 메모리를 판단하기보다 측정 도구, 다른 프로세스의 사용량, 실제 할당 실패 여부를 함께 확인해야 합니다.
  5. 측정 실패를 결측값으로 조용히 처리하지 않습니다 잘못된 속성 이름으로 발생한 오류가 포괄적인 except 처리에 가려져 모든 계단 높이에서 속도가 결측으로 기록됐습니다. 핵심 지표를 계산하지 못한 경우에는 원인을 명시하고 해당 평가를 실패로 처리해야 합니다.
  6. 변위와 이동거리를 구분하고 좌표계를 맞춥니다 몸통 기준 속도 명령과 무작위 초기 방향을 사용한 평가에서 월드 좌표계의 X 변위 평균은 0.041m였습니다. 서로 다른 진행 방향의 부호가 상쇄되므로 이 값만으로 보행 거리를 판단할 수 없습니다. 출발점에서의 평면 변위 크기나 명령 방향으로 투영한 변위처럼 평가 목적에 맞는 지표가 필요합니다.
